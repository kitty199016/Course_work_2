# Архитектура и документация проекта: Мониторинг самолетов (Aeroplane Tracker)

Консольное приложение на Python для получения, фильтрации и сохранения данных о самолетах, пролетающих над определенной страной в режиме реального времени. Проект демонстрирует применение паттернов проектирования, объектно-ориентированного программирования (ООП), строгой типизации данных и слоистой архитектуры.

---

## 🛠 Технологический стек

* **Язык программирования:** Python 3.10+
* **Валидация данных и модели:** Pydantic v2
* **Работа с JSON:** orjson (высокопроизводительный парсер)
* **Тестирование:** pytest, unittest.mock

---

## 📐 Архитектура проекта

Приложение построено по принципам декомпозиции и слабой связанности компонентов. Архитектуру можно разделить на следующие ключевые слои:

### 1. Слой данных и моделей (Models)
Использует **Pydantic** для строгой валидации сырых данных, поступающих из внешних API и файлов.
* `Aeroplane` — модель характеристик отдельного воздушного судна (позывной, высота, страна регистрации и т.д.).
* `AeroplanesDB` — контейнер для списка самолетов. Содержит бизнес-логику фильтрации и сортировки (метод `get_top_filtered_planes`).
* `OpenStreetDataCoordinates` — модель для хранения географических координат (bounding box) выбранной страны.

### 2. Слой работы с внешними API (Adapters / Network)
Интегрируется с внешними веб-сервисами без смешивания логики запросов с бизнес-логикой.
* `OpenStreetAPI` — взаимодействует с **OpenStreetMap (Nominatim API)**. Принимает текстовое название страны и возвращает её географические границы.
* `AeroplaneAPI` — взаимодействует с **OpenSky Network API**. На основе координат от `OpenStreetAPI` запрашивает актуальный список самолетов в воздушном пространстве выбранной страны.

### 3. Слой хранения данных (Repository Pattern)
Для изоляции работы с файловой системой применен паттерн **Репозиторий** совместно с паттерном **Фабрика**:
* `BaseAeroplaneRepository` — абстрактный базовый класс, задающий интерфейс для сохранения, загрузки и удаления данных.
* `JsonAeroplaneRepository` / `CsvAeroplaneRepository` — конкретные реализации драйверов для сохранения данных в форматы `.json` (через `orjson`) и `.csv` (через встроенный модуль `csv`).
* `AeroplaneRepositoryFactory` — фабричный класс, который динамически определяет требуемый тип репозитория на основе расширения файла (`.json` или `.csv`).

### 4. Слой пользовательского интерфейса (UI / CLI)
* `main.py` (`user_interaction`) — консольный интерфейс (CLI), оркеструющий работу всех слоев. Он собирает требования пользователя, запрашивает данные из API, передает их на фильтрацию и отправляет на сохранение в репозиторий.

## 📁 Структура проекта

```text
├── data/                       # Директория для сохранения отчетов (JSON/CSV)
├── models/
│   ├── aeroplane_model.py      # Pydantic-модели Aeroplane и AeroplanesDB
│   └── streetmap_models.py     # Pydantic-модель OpenStreetDataCoordinates
├── src/
│   ├── __init__.py
│   ├── api_client.py           # Базовый HTTP-клиент для отправки запросов
│   ├── base_adapters.py        # Базовый класс AeroAPI
│   ├── aeroplanes_api.py       # Класс AeroplaneAPI (OpenSky Network)
│   ├── openstreet_api.py       # Класс OpenStreetAPI (Nominatim OpenStreetMap)
│   └── manager.py              # Репозитории (JSON/CSV) и фабрика AeroplaneRepositoryFactory
├── tests/                      # Модульные и интеграционные тесты (pytest)
│   ├── test_aeroplanes_api.py
│   └── test_repository.py
├── main.py                     # Точка входа в приложение (Интерфейс пользователя)
├── README.md                   # Документация проекта
└── requirements.txt            # Зависимости проекта
```

## 🚀 Установка и запуск

### 1. Клонирование репозитория и переход в папку
```bash
git clone <url_вашего_репозитория>
cd Course_work_2
```

### 2. Настройка виртуального окружения
```bash
python3 -m venv .venv
source .venv/bin/activate  # Для Linux/macOS
# или
.venv\Scripts\activate     # Для Windows
```

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Запуск приложения
```bash
python main.py
```

## 🧪 Тестирование

Проект покрыт модульными тестами с использованием `pytest`. Внешние сетевые запросы к API и вызовы к файловой системе полностью изолированы (заглушены) с помощью `unittest.mock` и `monkeypatch`, что гарантирует скорость и стабильность прохождения тестов без фактического обращения к серверам или диску.

Запуск тестов:
```bash
pytest
```
